A valid citation can still support the wrong answer

Karan Kapoor Applied AI Lab · October 27, 2026

Technical note v0.1. An AI-assisted diagnostic study, not peer-reviewed research. This note describes two scripted examples, not responses generated by a model.

Question

Does checking that a quote exists in a source establish that the answer is correct? In an evidence-backed product workflow, a citation validator can successfully verify a source ID and quoted text while accepting an unrelated claim. The distinction matters when deciding whether a response is ready for a user or needs review.

Reproducible method

The study reuses the offline comparison harness and one development fixture. The question asks why a user cannot finish signup. Its only source says: “The signup verification link returns an expired-token error.” The reference expects an answered status and source S01.

Two scripted answers use exactly that quote and source ID. The control repeats the source as its claim. The counterexample instead claims that revenue increased by a billion dollars. Both retain the same answered status and expected source set. Each is checked by the real validation and scoring code; no language model, external provider or paid inference is used.

The harness checks answer structure, permitted source IDs, literal quote membership, the expected answer/abstention label and the exact reference source set. It intentionally reports semantic correctness as unknown and human review as pending. Scripted zero latency is a placeholder and is not a measured performance result.

Observed result

AnswerAutomatic checksAuthored support label
Signup link returns an expired-token errorPassSupported
Revenue increased by a billion dollarsPassUnsupported

Both scripted answers pass all automatic checks. The second claim does not follow from the signup evidence. A single valid counterexample is sufficient to show that passing these particular checks does not guarantee claim support. The result does not estimate how often any model produces unsupported claims.

The support labels were authored for this diagnostic. They are not an independently reviewed evaluation dataset. The machine-readable result preserves that distinction and leaves the harness semantic score null.

Product implication

Keep structural integrity and answer quality as separate release criteria. A valid citation is useful: it makes inspection possible and can reject fabricated references. It is an incomplete quality gate. A product should also check whether the evidence supports the actual claim, whether important contradictions were preserved, and whether abstention was appropriate.

For a higher-risk decision, route the answer to a reviewer who can inspect the claim beside the cited source. If an automated entailment judge is added later, measure and calibrate that judge against independently reviewed examples rather than treating its agreement as ground truth. This implementation has not added or evaluated such a judge.

Limits and next experiment

The demonstration contains two deliberately constructed examples and one source. It does not test live generation, prompt-injection robustness, production use, user outcomes or statistical significance. No provider ranking or model error rate follows from it. Exact source-set agreement also depends on the quality and completeness of the reference labels.

A useful next experiment is to label supported, contradicted, unrelated and incomplete answers using multiple reviewers, retain their disagreements, and reserve an untouched test set. Compare structural checks with human judgments before evaluating an additional automated judge. Report reviewed coverage and abstention errors alongside any aggregate score.

Reproduce and inspect

Run npm run study:citations from the repository root. The script uses the same harness exercised by the automated test “literal citation matching does not establish claim entailment.”
