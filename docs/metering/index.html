      Generated replay evidence

      Methods, boundaries and a three-minute walkthrough
      1. Retry safety: choose Duplicate delivery. One extra event arrives, but the charge remains $9.76. An event ID is an idempotency key; matching payloads collapse.
      2. Data integrity: choose Conflicting usage. Both occurrences of the conflicting event are quarantined. The visible charge falls to $5.36, but that is incomplete usage, not savings. HOLD takes precedence over a cheaper bill.
      3. Commercial readiness: return to Clean usage, set pricing to 125%. The replay charge becomes $12.20 and exceeds the $10 batch budget. Raising the threshold and acknowledging reviews passes only these replay checks.
      4. Reproducibility: export the metadata ledger, rejected rows, rate card, policy and configuration. The export is an evidence packet, not an invoice or a provider bill.

      Billing policy: only completed requests are charged. Failed and aborted requests are zero-rated here even if tokens are recorded; real providers may charge differently. Multiple completed events with different IDs for the same logical request are quarantined, not silently billed twice. Event conflicts are detected within this batch only; no durable cross-batch idempotency store exists.

      Fictional baseline prices per million tokens: swift $2 input / $8 output; deep $10 input / $30 output. Integer milli-USD rates multiplied by token counts produce exact nanodollars. Proposed pricing rounds each line to a nanodollar; the invoice-like batch display rounds half up once to cents. No taxes, FX, credits, tiers, cached tokens or late-event reconciliation are implemented.

      This is a product and control-design prototype. It does not route models, measure model quality, operate a GPU fleet or certify reliability. Complements Telemetry Lab and the feedback investigation workspace.
